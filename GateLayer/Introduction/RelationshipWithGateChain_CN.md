# GateLayer 与 GateChain 的关系

## 职责分工

*   **GateLayer（L2 执行层）**：
    *   基于 **OP Stack** 的 **EVM 执行环境**与 **Sequencer**；
    *   负责**快速、低费**的交易处理与应用部署；
    *   通过 **Batcher/Proposer** 把批次与**状态根**提交到 GateChain；
    *   集成 **LayerZero** 等跨链协议，提供互操作能力。
*   **GateChain（结算 + 数据可用性层）**：
    *   作为 **结算与最终性来源**，承载 Rollup 合约；
    *   提供 **Blob** 以存储批次数据/状态根（降低成本、保证可验证）；
    *   由 **GT 质押与验证者网络**提供安全性与治理；
    *   负责金库/治理等经济与管理职能。

## 安全与最终性

*   L2 的交易在 GateLayer 上**先快确认**；最终性以 GateChain 的 **rollup 合约确认**为准。
*   GateChain 的 **GT 质押/验证者**与共识，提供**结算安全**与**数据可用性**保障。

## 费用与经济流

GateLayer 上的交易费用被设计为两部分的总和，以准确反映其在 L2 上的执行成本和在 L1 上的数据存储成本。

*   **L2 执行费 (Execution Fee)**：
    *   这部分费用用于支付在 GateLayer EVM 中执行交易所需的计算资源。
    *   它遵循标准的 **EIP-1559 模型**，由 `基础费 (baseFee)` 和 `优先费 (priorityFee)` 组成。这部分费用是 Sequencer 的主要收入来源。

*   **L1 数据费 (Data Fee)**：
    *   这部分费用用于支付将交易数据作为 **Blob** 发布到 GateChain（L1）的成本，以确保数据的安全和可用性。
    *   它是 L2 能够提供比 L1 低几个数量级费用的关键，因为 Blob 的存储成本远低于传统的 `calldata`。

*   **费用流向与治理**：
    *   用户支付的总费用 (`L2 执行费 + L1 数据费`) 由 Sequencer 代收。
    *   Sequencer 从中支付将数据提交到 L1 的成本 (`L1 数据费`)，剩余部分 (`L2 执行费`) 作为其运营利润。
    *   未来可通过治理对 Sequencer 的收益进行再分配，例如部分返还给生态金库或用于激励网络参与者。

## 跨链与互操作

*   应用层通过 **LayerZero/生态桥**实现与多链资产/消息互通；
*   互操作的**安全锚点**是 GateChain 上的最终性：跨链释放/结算以 L1 确认为准。

## 可用性与可验证

*   交易批次与状态根持久化在 **GateChain 的 Blob** 与 Rollup 合约；
*   任意方可基于 L1 数据**重建与验证 L2 状态**，满足可验证与审计需求。

## 运维与可观测

*   L2 提供 **RPC / WS**、节点、索引服务与 **Explorer**；
*   合约地址、网络参数、桥接入口在文档中集中给出（Get Started / Developers）。
